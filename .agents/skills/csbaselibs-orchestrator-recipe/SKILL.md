# csBaseLibs Orchestrator Recipe Management

## Overview

This skill guides the agent in inspecting, auditing consistency, updating, and maintaining the **csBaseLibs** build recipe. `csBaseLibs` uses the `csOrchestrator` framework to define cross-platform base-libraries build pipelines in Python and generate corresponding GitHub Actions CI workflows.

## Dependencies

- **Python**: `>= 3.11` in active `.venv`
- **csOrchestrator**: Available as an editable package in the local environment
- **Tools**: `pre-commit`, `ruff`, `mypy`, `pytest`

## Quick Start

To audit recipe consistency and re-generate the GitHub Actions CI workflow:

```bash
# 1. Re-generate GitHub Actions workflow from csBaseLibs.py
./csBaseLibs.py generate-github-workflow

# 2. Run quality checks and ensure git hygiene
pre-commit run --all-files
```

## Workflow

Follow these steps when interacting with or modifying the `csBaseLibs` build recipe:

### 1. Recipe & Consistency Audit
Inspect the core configuration files before making changes or upon request:
- [`csBaseLibs.py`](file:///home/sceriani/myWorkspace/csBaseLibs/csBaseLibs.py): Core pipeline definition, version, and repository list.
- [`pyproject.toml`](file:///home/sceriani/myWorkspace/csBaseLibs/pyproject.toml): Project metadata and versioning.
- [`csBaseLibs/cs_orchestrator_config.py`](file:///home/sceriani/myWorkspace/csBaseLibs/csBaseLibs/cs_orchestrator_config.py): Placeholder orchestrator config (empty for now; the qt6 toolchain mapping will come automatically from the csQt6 download).
- [`tests/`](file:///home/sceriani/myWorkspace/csBaseLibs/tests): Placeholder tests; real recipe tests are added later.

**Verification Checklist (Strict Fail-Loud Policy):**
- **Extra Files**: Check every path passed to `additional_files_list` in `create_default_orchestrator()` (e.g. `Path("csBaseLibs/cs_orchestrator_config.py")`). Verify that every referenced file exists on disk.
- **Version Alignment**: Verify that `version` in `csBaseLibs.py` (e.g. `0.1.0`) aligns with `version` in `pyproject.toml` and artifact package names (`csBaseLibs-<version>-...`).
- **Repository List**: Verify that every repository in `repos` is a known csOrchestrator-supported repo and that its `BuildConfig` (`DEBUG_RELEASE_RELWITHDEBINFO_PARANOID`, or `None` for checkout-only repos like `csCMake`) matches the repository's intended configuration.
- **Precompiled Libraries Gap**: The "Get Precompiled Libraries" phase (3rdPartyBaseLibs + csQt6) is currently disabled (it relied on `create_steps_to_get_libs_from_manifest`, removed from csOrchestrator). `csBaseLibs/cs_orchestrator_config.py` stays an empty placeholder for now; the qt6 mapping will come automatically from the csQt6 download. Reimplement the phase before re-enabling it.
- **SDK Vendoring**: `csorchestratorsdk/portable/` is autogenerated from `csOrchestrator`; do not edit manually. If it needs updating, re-export it by running `./csBaseLibs.py generate-github-workflow`.

> [!IMPORTANT]
> If any consistency check fails (missing extra file, mismatched version, unknown repository), **fail loudly**. Report the exact discrepancies to the user for guidance rather than silently continuing or guessing.

### 2. Local Execution Policy (Build Guard)
- **DO NOT run full local builds of the base libraries** (e.g., executing all phases of `./csBaseLibs.py` locally). Building every library on the full matrix requires significant time, disk space, and RAM.
- Only run unit tests (`pytest`) or dry-run validation when checking local configuration logic.

### 3. CI Workflow Re-generation
Whenever `csBaseLibs.py`, the repository list, or execution phases are modified, re-generate the GitHub Actions workflow:

```bash
./csBaseLibs.py generate-github-workflow
```

- Verify that [`.github/workflows/csBaseLibs.yml`](file:///home/sceriani/myWorkspace/csBaseLibs/.github/workflows/csBaseLibs.yml) has been updated with the modified phases and matrix.
- Inspect the git diff using `git diff .github/workflows/csBaseLibs.yml` to ensure changes match expectations.

### 4. Code Quality & Pre-commit Verification
Before concluding any changes, run the repository's validation hooks:

```bash
pre-commit run --all-files
```

If hooks report formatting errors or auto-fix lines:
1. Review the modified files.
2. Re-run `pre-commit run --all-files` to ensure all checks pass cleanly (`Passed`).

### 5. Documentation Synchronization
If recipe arguments, version, or repository configurations were updated:
- Update [`README.md`](file:///home/sceriani/myWorkspace/csBaseLibs/README.md) to keep the included-libraries table, build matrix, and command instructions accurate.

## Common Mistakes

1. **Attempting a full local build**: Running `./csBaseLibs.py` without understanding that it will attempt to download and build all base libraries. Full builds are meant for CI runners or dedicated build machines.
2. **Forgetting to re-generate the workflow**: Modifying `csBaseLibs.py` without running `./csBaseLibs.py generate-github-workflow`, leaving `.github/workflows/csBaseLibs.yml` out of sync with the Python recipe.
3. **Missing extra files in release**: Adding a file to `additional_files_list` in `csBaseLibs.py` that does not exist or has a typo in its relative path, causing release packaging jobs to fail in CI.
4. **Version mismatch**: Updating `version` in `csBaseLibs.py` without updating `pyproject.toml` or the artifact names (`csBaseLibs-<version>-...`).
5. **Re-enabling the precompiled-libraries phase prematurely**: It requires the reimplemented manifest recipe in `csOrchestrator`; the config stays an empty placeholder until then (the qt6 mapping will come automatically from the csQt6 download).
